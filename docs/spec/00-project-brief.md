# CloudQuest — Project Brief

**Working name:** CloudQuest (name/domain/trademark availability not yet checked)  
**Tagline:** Learn cloud by solving real-world challenges.  
**Status:** Hackathon concept and implementation brief.

## Product definition
CloudQuest is a multi-cloud learning platform that teaches cloud fundamentals through original interactive challenges, guided architecture diagrams, and spaced revision. Learners investigate a situation, make a decision, understand consequences, and apply concepts in a new context.

CloudQuest is an unofficial educational product—not a certification exam simulator, provider-endorsed product, production architecture validator, or cloud deployment service.

## Audience
- Beginners learning cloud fundamentals.
- Learners preparing for entry-level cloud certifications.
- Students and early-career IT practitioners.
- People comparing concepts across Azure, AWS, Google Cloud, and cloud-neutral foundations.

## Core loop
Choose a track → solve a scenario → receive reasoning and objective mapping → retry with a new situation or apply the concept in the Architecture Canvas → review weak concepts → inspect evidence-based progress.

## Product pillars
1. **Scenario Lab:** original decision, diagnosis, security, availability, governance, and cost scenarios.
2. **Architecture Canvas:** build conceptual diagrams and run deterministic educational “what if?” simulations. No real cloud resources are provisioned.
3. **Revision Studio:** revisit concepts using a simple, transparent spaced-review schedule.
4. **Multi-cloud tracks:** provider-neutral learning engine plus separate, versioned Azure/AWS/Google Cloud content packs.

## Product principles
- Learning value before feature count.
- Friendly, accessible, responsive UX with progressive disclosure.
- Original content mapped to public objectives and authoritative sources.
- Honest metrics: practice mastery is not a pass guarantee.
- Explain why decisions work or fail.
- Clearly disclose simulation assumptions and limitations.
- Modular monolith; avoid premature microservices.

## Hackathon MVP
- Landing page and guest-accessible sample challenge.
- Track selector and learner onboarding.
- One polished, original Azure scenario pack.
- Scenario feedback, hints, and fresh transfer retry.
- Revision queue and evidence-based progress.
- One guided Architecture Canvas challenge with a small node palette and deterministic rules.
- Small neutral or AWS sample pack to prove extensibility.
- Account UI; real authentication only if a trusted provider is configured.
- Accurate README, tests, architecture notes, and demo script.

## Non-goals
- Real cloud provisioning or cloud-account connection.
- Exact bill estimates or live provider API integration.
- Full professional diagramming suite.
- Broad catalog for every provider/certification.
- AI-generated authoritative content without review.
- Microservices, social feed, payment system, or enterprise administration.

## Success criteria
A first-time user can quickly understand the product, try a challenge without forced signup, learn from feedback, complete a guided canvas simulation, see their progress persist within the supported mode, and understand what is real versus simulated.
